# Browser workflow coverage matrix

Every user-facing change must update this matrix and a Playwright scenario in
the same pull request. See the mandatory rule in the test-driven-development
skill.

| Feature area | Current UI coverage | Required follow-up |
| --- | --- | --- |
| OTP sign-in | Covered — activated, reset, forced-password, and test-fixture accounts complete the email OTP UI path; `LOGIN_SUCCESS` is asserted after `OTP_VERIFIED`; a status transition between factors is denied and audited; unit/integration coverage validates pending age, expiry, replay rejection, attempt limits, and IP-scoped throttling | Invalid OTP browser path |
| Reception, triage, doctor, lab, pharmacy | Covered — a doctor submits two catalog lab tests and two catalog prescriptions in one consultation and the browser test asserts one PHI-free event per created order; queue transitions wait for every linked order, and a pharmacist refusal returns the encounter to its assigned doctor. Post-commit routing revocation records `WORKFLOW_ROUTING_FAILED` rather than a false authorization denial. | A test-only trigger covers the post-commit revocation boundary, but does not exhaustively prove every database-specific concurrent interleaving |
| Patient registration contact validation | Covered — Kenyan-format validation and distinct normalized emergency-contact number rejection | Additional browser coverage for optional demographic fields |
| Patient-number generation | Covered — prepopulated locked field and a tampered-number rejection | Exercise the rare database-collision retry with an end-to-end test double if one is introduced |
| Doctor/lab/pharmacy history and pharmacy payment | Covered — a currently assigned doctor owning the active visit sees rendered vitals, diagnoses, lab results, prescription details, and dispensing outcome after the staff workflow; revoked and wrong doctors are denied without disclosure | Empty-history states |
| Doctor assignment revocation and IDOR | Covered — a real active consultation is created, the admin unassign form returns it to the existing nurse queue and releases the doctor for selection, and dashboard/list/detail/history/profile plus valid-CSRF mutation attempts are denied with no forged write; nurse rerouting proves the original protected record remains intact and the denial audit is patient-scoped `HIGH_RISK` | Deterministically scheduled concurrent revocation remains unexercised |
| Role denial | Receptionist-to-doctor denial plus revoked-doctor and wrong-doctor object-level denial covered | Remaining role/object combinations |
| Direct include access | Covered — lowercase and mixed-case billing-partial URLs are denied without PHP diagnostics or fragment content | Repeat under Apache/XAMPP because the standard runner uses PHP's built-in server |
| Account activation | Covered — administrator creates a pending user; activation validates mismatch and password policy failures, consumes the emailed token, and signs in through OTP | Expired-token path |
| Change password | Covered — a CLI-guarded, disposable-database-only fixture drives forced and voluntary changes, the 12-character policy, mismatch, incorrect-current-password, weak/unchanged-password denial, forced logout, fresh OTP, and replacement-password login | CSRF failure path |
| Administrator reset password | Covered — reset email token consumption and OTP login with the replacement password | Expired-token path |
| Forgot password | Recovery request and account-enumeration protection covered; hostile browser flow proves IP-scoped request throttling blocks follow-on reset mail | Consume reset link and verify replacement-password login |
| Administrator user management | Covered — create, activate, deactivate/reactivate, password-reset, UI/server self-deactivation protection, and proof that deactivate/reactivate does not revive an existing session | Role-edit UI is not currently implemented |
| Authentication failure privacy | Covered — unknown, inactive, wrong-password, fifth-attempt lockout, and already-locked accounts all render the same message; login responses are no-store and attacker-chosen/URL session IDs are rejected | Timing distributions remain environment-dependent and are covered structurally rather than with flaky wall-clock assertions |
| Mutation request boundary | Covered — all 21 state-changing controllers receive missing, wrong, and array-shaped CSRF tokens through real HTTP requests; each returns the deterministic generic 403, records exactly one safe blocked/suspicious audit event, and preserves a checksum of every non-audit table. Valid-CSRF array identifiers fail without a 500 or ID-1 coercion. Logout and administrator reset reject GET with 405, while tokenized POST logout remains available in top and sidebar navigation | The database checksum assertion intentionally proves persisted state; in-memory service side effects would need route-specific instrumentation if any are introduced later |
| Patient self-service | Covered — linked profile, records, labs, prescriptions, dashboard counts, and direct cross-patient ownership denial | Empty self-service data states |
| Reports | Doctor operational report covered — active consultations and doctor-owned pending lab/prescription counts are asserted from real records | Add remaining role reports |
| Visit billing and payments | Covered — receptionist adds server-priced service charges, records cash receipt and pending insurance claim states, and a linked patient sees only their own paid bill; `BILLING_VIEWED`, `BILLING_CHARGE_ADDED`, and `PAYMENT_RECORDED` are asserted without payment references; a forged patient mutation is rejected without changing the total | Insurance settlement and administrator view |
| Forensic audit integrity | Covered — unit/SQLite tests exercise v1/v2 vectors, authenticated key checks, correct-key tamper versus wrong-key classification, non-positive/extra physical-row coverage, format downgrade ordering, gaps/forks, partial scopes, anchors, rollback, retention batching, owned read snapshots, same-snapshot recent-row quarantine, caller-transaction non-interference, and concurrent WAL appends. Opt-in MariaDB tests force a `READ COMMITTED` session, prove verification takes its own non-blocking consistent snapshot while an append commits, retain definite tamper detection, apply the migration twice, and reject rather than repair a legacy zero sequence. Browser coverage proves missing-anchor `UNKNOWN` evidence is `SUCCESS`/`NORMAL` and does not inflate dashboard counters, suppresses self-referential integrity events for an unanchored suffix, and keeps a definite local `FAIL` visible while quarantining forged recent rows. | External anchor storage administration must be tested in the target deployment |
| OWASP ZAP passive baseline | Covered — `scripts/run-zap-baseline.ps1` rebuilds the disposable UI database, starts the local app, and produces HTML/JSON/XML passive-scan reports; `npm run test:zap` is a shortcut | Authenticated ZAP scan only after explicit written authorization and a disposable target scope |
